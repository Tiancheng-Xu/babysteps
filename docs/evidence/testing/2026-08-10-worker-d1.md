# BabySteps Worker/D1 Phase 2 本地验证证据

## 结论

2026-08-10，BabySteps 已在本地完成 Cloudflare Worker/D1 链下边界：链上任务与 D1 富内容稳定绑定、challenge-sign-verify 会话、用户名更新、Provider 草稿、交易与事件核验、购买后评论和 Owner 软隐藏。Worker 测试共 47 个，TypeScript、Biome 与 Wrangler dry-run 均通过。

本证据的边界是：`local only; no remote D1 or Worker deployment`。本阶段没有创建远程 D1、部署 Worker、变更 DNS、调用 Sepolia 写交易、创建 AWS 资源或改变生产页面。

## 参考架构取长补短

本阶段对照 作业参考清单、公开可读取的 `Chi111/web3-university` 和学习资料中的 Worker/Lambda、Hono/AWS 架构图，吸收以下做法：

- 同一个稳定业务键连接链上事实与链下富内容
- 写操作使用短时 challenge、一次性 nonce 和防重放消费
- 评论写入前重新读取链上购买事实
- 绑定、审核与故障保留可重放的审计证据

BabySteps 没有复制 MockUSDC、测试水龙头、Worker 私钥执行器、PinMe，也没有引入当前负载不需要的 VPC、NAT Gateway、RDS 或多可用区数据库。不可导出签名仍保留在后续 Lambda/KMS 边界。

## D1 数据边界

`D1 migrations` 创建以下业务表：

1. `profiles`
2. `auth_challenges`
3. `sessions`
4. `task_drafts`
5. `published_tasks`
6. `comments`
7. `audit_logs`

D1 保存富内容、用户名、评论、nonce/session 哈希和审计。链上继续拥有 Provider、payee、任务状态、随机价格与时长、购买、完成和证书事实。D1 不保存儿童姓名、生日、学校、位置、健康、喂养、睡眠或照片。

## 认证与威胁控制

- challenge 固定 domain、URI、chain ID、wallet、action、nonce、issued-at 和 expiry
- nonce 使用 Web Crypto 生成；D1 只保存 SHA-256，不保存原 nonce
- 签名恢复地址必须等于 challenge wallet，篡改消息会被拒绝
- nonce 使用 `used_at IS NULL AND expires_at > now` 条件更新，并发重放测试只允许一次 `201`
- 会话令牌为 32 字节随机 opaque token；D1 只保存 SHA-256
- Cookie 不设置 Domain，满足 `__Host-` 约束；注销写 `revoked_at`
- 日志只记录 request ID、method、path、status、duration，不记录 Cookie、签名、用户名、评论正文或 RPC 凭据

## TDD 与故障复盘

1. 健康与 schema 测试最初分别返回 `404` 和仅存在框架迁移表；实现 7 表 migration 后 3/3 通过。
2. Workerd `1.20260801.1` 只支持 compatibility date 到 `2026-08-08`，最初配置 `2026-08-10` 无法启动；改为运行时支持的最新日期后正常。
3. Wrangler 4.120.0 明确提示生成 runtime types 已取代手写 Workers types；移除直接依赖并保留 `wrangler types --check`。
4. 认证与资料测试先出现 15 个 404；实现后并发防重放、错签、过期、Cookie、注销、资料和审计全部通过。
5. task identity/metadata 先出现 9 个功能失败；实现稳定 key 与 canonical hash 后通过。
6. task 路由先出现 7 个 404；首次 GREEN 后发现同一测试文件共享 D1 状态，增加每例清理后证明幂等与冲突行为不是污染数据造成。
7. 评论路由先出现 9 个 404；实现购买查询、编辑和软隐藏后全部通过。
