# BabyCoin 余额数字友好化设计

## 目标

让家长中心的链上余额在桌面端和移动端都能快速读懂，同时保留链上原始精度，不改变合约、余额计算或交易行为。

## 已确认方案

- 主数字最多展示 4 位小数，去掉末尾无意义的 0；例如 `10.650166471630484868` 展示为 `10.6502`，`27` 仍展示为 `27`。
- `BABY` 作为独立、较小的单位显示，避免与主数字争夺视觉层级。
- 完整链上数值保留在可访问的辅助说明与 `title` 中。
- 数字使用等宽字形并允许在窄屏安全换行，不产生横向滚动。
- “可用余额”解释为可消费、会变化；“累计成长奖励”解释为决定成长阶段、只增不减。
- 375、390、430px 使用单列卡片；1440px 使用双列卡片。
- 同一格式化规则复用于家长中心、市集余额、兑换报价与活动奖励显示。

## 非目标

- 不改变 ERC-20 的 18 位精度。
- 不四舍五入后用于交易、授权或余额判断；格式化仅用于展示。
- 不修改合约、Worker、AWS 或 Cloudflare 配置。

## 验收

1. `10.650166471630484868 BABY` 的主视图显示为 `10.6502 BABY`，完整值仍可读取。
2. 整数不补小数位，极小非零值不会误显示为 `0`。
3. 可用余额与累计奖励的含义在卡片内直接说明。
4. 375、390、430、1440px 无根级横向溢出，数字不互相覆盖。
5. 前端单测、类型检查、构建及公开产物扫描通过。
