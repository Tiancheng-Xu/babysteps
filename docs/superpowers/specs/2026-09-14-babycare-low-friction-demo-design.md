# Babycare 海外亲子社交演示低门槛设计

## 目标

把 BabySteps 从“先理解测试网与钱包”调整为“先完成一次亲子陪伴，再按需登录与使用链上能力”的中国 + 日本市场演示版本。首屏必须在三分钟内给访客可感知价值，同时保留现有真实 Web3、身份、权限和 Evidence 边界。

## 产品原则

1. 访客优先：未登录、未连接钱包也能选择宝宝阶段与城市，领取并完成一个三分钟亲子任务。
2. 渐进式身份：只有跨设备保存、家庭协作、活动报名或权益领取时才引导 Google / 邮箱登录。
3. Web3 后置：钱包、Sepolia、BabyCoin、抽卡与链上凭证进入“进阶体验”，不占据首屏主路径。
4. 隐私最小化：本地试用只保存粗粒度阶段、市场、城市和完成状态，不保存姓名、生日、照片、健康或精确位置。
5. 诚实边界：不新增或伪装中国、日本社交后台；城市选择只用于本次演示的本地推荐。

## 首次体验

首页先展示品牌价值和“三分钟开始”卡片。用户选择宝宝阶段、中国或日本市场及一个粗粒度城市后，立即获得匹配的亲子任务。点击开始后可标记完成，页面清楚说明记录只保存在当前浏览器，并提供“登录后长期保存”的后续入口。

## 页面调整

- 首页：品牌与亲子陪伴优先；新增访客任务；现有钱包、成长账本、赠送和链上便签收进进阶区域。
- 成长任务：先解释家庭活动价值；未连接钱包时提供可继续的登录/了解入口，不再显示不可操作的“先连接钱包”死按钮。
- 家长中心：先说明本地试用与长期家庭档案的区别，再呈现进阶钱包与链上记录。
- 个人中心：强调 Google / 邮箱是推荐入口，无需预先理解钱包；签名和 Smart Wallet 作为可信保存的进阶说明。
- 导航：面向家庭的核心入口优先，机构、链上兑换、性能和 Evidence 标识为进阶/证明入口。

## 状态与数据

本地状态使用带版本号的 localStorage 记录：宝宝阶段、市场、城市、推荐任务 ID、开始时间和完成状态。解析失败时回退到无状态；所有字段均为固定枚举或粗粒度选项。服务端渲染不读取浏览器状态。

## 验收

- 单元与组件测试覆盖推荐、存储、恢复、完成和无钱包 CTA。
- Web 全量测试、类型检查、Biome、生产构建通过。
- 375 / 390 / 430 / 1440 无根级横向溢出，关键触控目标至少 44px。
- BackstopJS reference 必须先审阅，candidate 差异人工确认后才能接受。
- 生产发布使用 GitHub PR 与 Cloudflare Pages Git Integration；不启动 AWS Runtime。
